# 0.2.11：帧内 MEM-AP 配置复用

日期：2026-10-15。固件 0.2.11，连接服务／公开 SDK 仍为 0.2.6，协议和调用布局不变。标准 CMSIS-DAP 继续走虚拟 USB；本次性能改动位于板端订阅访问路径，没有修改 ARM SWD 位操作内核、Windows 内核驱动或原 Orbit 工作区。

## 行为与失效边界

原实现中，每次内部 word／block／scattered 访问都写 DP SELECT=0、AP CSW=32-bit，然后设置 TAR 并读写。十条独立四级链仍需每帧 50 个物理读取、十个 DAP 调用，重复配置增加耗时。

现在仅在本模块确认 AP 配置有效时省去 SELECT／CSW 前置写入。每个新帧／RTT poll、每个排队的外部命令或 close、控制屏障、模块初始化与会话关闭都会使状态失效；任何部分完成或失败的 DAP 响应也会使状态失效。下一次访问重新写完整配置。原始 CMSIS-DAP 命令、复位和 owner 变化都经过统一执行器的命令边界，没有增加第二条 SWD 链路。

每次仍明确设置 TAR；指针及目标数据不进入 AP 状态缓存，指针仍逐帧重新解析。每个执行器工作块最多八个物理读取，控制队列优先，RTT 写入完成不明时的保留／核对规则不变。无外部命令打断的十批次帧，前置寄存器写入可由二十次减至两次；物理读取数及 DAP 调用数没有减少。

源码位于 firmware/components/debug_probe/rmlink_capture.c、swd.c 和 include/rmlink_capture.h。版本由 firmware/CMakeLists.txt 与 swd.c 同步声明。没有保留先前 0.2.9 的批次排名或 0.2.10-profile 的计时代码。

## 模型、构建与功能验收

真实采集 C 源码模型直接计数 SELECT／CSW 写入，验证一帧多批次仅设置一次、下一帧重新设置、叶数据重新读取、帧中穿插外部命令后恢复完整设置，以及控制屏障、会话关闭与失败恢复。模型模拟了错误 AP bank／CSW；故意关闭复用时，前置写入计数断言失败；移除模拟执行器的命令失效边界时，错误 bank／CSW 检查失败。

既有指针改向、32 字段／四级深度、1/2/4 字节、范围边界、部分响应、RTT 环形回绕、写完成不明、所有权、取消及有界溢出模型仍通过。初次将新专项放在旧测试之前时没有清零测试计数，旧 `reads==0` 断言失败；修复测试隔离后通过，失败日志保留。83 项主机测试及 CPU0 的 TCP64／512 构建通过；新增两项主机故障检查验证板端丢弃会提前终止、保留失败录制，且录制 CRC 故障不会覆盖原始失败原因。

同一 STM32F103C8 上，虚拟 USB OpenOCD 完整 64 KiB 擦写／校验、独立回读、选项字节、寄存器／RAM、断点／单步、DWT、软件复位和异常／取消通过；本次烧录／校验 12322.99 ms，仅是该轮功能计时，不声称标准烧录提速。pyOCD 0.45.1 暂停、读 PC、继续通过。fixture 保留，Flash SHA256：`2a65c721fa1be9c4fcddba2a32bb96ccaeece439b517adb167f00ea928c031a4`。

无线严格三订阅录制 2008 帧、原生 USB64 录制 2056 帧，均通过独立哈希／CRC，严格模式 gaps 和 invalid_samples 为零；结束后 Wi-Fi 选路恢复。慢消费者、严格超期、指针字段及 RTT 连续重建另有独立结果。全部 18 种深度／共享与独立／独占与共存布局的两秒检查通过，包含改向、非法指针和有符号偏移。

真实控制检查为空载、十条独立四级链负载各 20 次暂停／继续。负载时暂停中位 82.69 ms、最大 175.63 ms，继续中位 54.25 ms、最大 168.96 ms；控制长尾目标仍未达标。C SDK 完成 40 帧 CRC 与游标续读检查。

## 同条件短测

普通 0.2.8 对照与本版使用同一目标、同一 fixture，CPU0、TCP512、电脑 2.4 GHz 热点，请求 SWD 4 MHz，实际 SWCLK 未仪表量测。Timeline 十个 32-bit 字段、叶节点间隔 64 B、请求周期 1 ms，同时运行四字段 Watch（100 ms）及 RTT（5 ms）。每类布局三次、每次五秒，以下为中位值。

这些叶字段均由 fixture 主循环更新；稳定计时期间指针节点位于预留 SRAM，链结构固定，另有单独的改向检查。不是并发修改对象时的原子快照测试。无线和主机负载未完全隔离；保留全部逐轮数据，没有只挑最快一次。

真实 Orbit 后端子进程另做五轮、每轮五秒，结果为 990.14、990.22、988.06、988.47、983.62 Hz，中位 988.47 Hz；0.2.8 同类历史中位为 936.28 Hz。该布局为共享三级链、末端连续 40 B 的十变量，只有第一个变量动态，其余为身份常量，不能套用到上表的 64 B 离散叶节点或十条独立链。五轮字段／RTT／暂停继续均通过、子进程退出码 0；已安装 VS Code 界面未验收，以前一次 Node 0xC0000409 原因仍未确定。

## 网络生命周期

健康空闲 20 秒保留 owner，三轮主动 STA 重连期间原生 USB owner 保留、80 次真实 CPUID 读取通过，新 TCP 可用时间约 2.74–2.88 秒，ESP32 未重启。第一次误在 Connector 运行时启动直接 TCP 检查，被脚本的连接独占保护拒绝；停服务后另存结果通过，最后恢复服务。这不等于真正电脑重启或静默半断连验收。
