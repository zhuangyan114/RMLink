# 指针批次均衡试验：未采用，恢复 0.2.8

2026-10-15。基于提交 `72e7a3b` 的实验分支代码，试验固件统一显示 0.2.9，必须结合镜像哈希区分 A–E；这些候选没有成为发布版本。默认源码和实际设备均恢复到通过验收的 0.2.8，连接服务／SDK 仍为 0.2.6，封存的 0.2.6 安装包未覆盖。

## 目的与取舍

0.2.8 按字段顺序推进指针：前八条链可能完成后，后两条链才继续。十条独立四级指针链每帧读取 50 个物理 word，模型中需要十个板内 DAP 批次。试验优先推进尚未深入的依赖，同样 50 个 word 可放入七个批次，每批最多八个物理读取。这里的批次是板内调用，不是七次网络往返，也没有减少实际读取的 word 数。

模型和实板功能正确，但性能存在取舍：独立三级／四级链略有改善，共享二级链却多轮变慢。最后一个 E 候选仍未消除回退，因此保留补丁供分析，恢复 0.2.8，未把试验写入默认实现。没有用减少批次数直接推导采样率提升。

## 测试条件

同一 ESP32-S3、STM32F103C8、保留的 fixture、GPIO4/5、CPU0、TCP512，电脑 2.4 GHz 热点。请求 SWD 4 MHz，实际 SWCLK 未仪表量测；NRST 缺线。fixture Flash SHA256：`2a65c721fa1be9c4fcddba2a32bb96ccaeece439b517adb167f00ea928c031a4`。

Timeline 十个 32-bit 字段、叶节点间隔 64 B、周期请求 1 ms；共存组额外运行四字段 Watch（100 ms）及 RTT（5 ms）。每个布局两秒、三次重复，表中为三次实际采样率的中位数。字段及 RTT 检查由真实连接服务／板端执行，无已安装 VS Code 界面参与。没有在矩阵过程中连续测量 RSSI，主机负载和无线环境未完全隔离，不能把几 Hz 差异推广为保证。

最初 0.2.8 与 A 各完成 54 轮：深度 0–4、共享／独立、独占／共存。C、恢复后的 0.2.8、D、E 各做 12 轮重点复测。完整逐轮数据、镜像身份和 SHA256 见 [机器记录](balanced-pointer-scheduler.json)。

## 各候选验证范围

| 候选 | 实现 | 已完成的检查 |

新模型还验证了最大 32 字段／160 word 的边界；把新批次数断言链接到 0.2.8 实现时按预期失败。功能检查通过不等于性能收益成立。

A 的持续采样在发现共享二级回退后，由测试程序主动关闭自己的会话以结束试验，原结果保留 `complete=false` 和 `Session closed/lost`。操作原因与会话身份已单独记录；这不是一次完成的十分钟验收，也不能据此判断设备发生断连。E 没有十分钟验收，没有生成 0.2.9 安装包。

可复查补丁为 [balanced-pointer-scheduler.patch](balanced-pointer-scheduler.patch)，基于 `72e7a3b`，仅含固件版本、采集实现与模型检查。已经通过 `git apply --check`，默认源码未应用。A 与 E 镜像分别保留在 artifacts/checkpoints/0.2.9 和其 candidate-e 子目录；同为 0.2.9 的候选不能混用验收记录。

## 恢复与录制复核

实板恢复的是先前封存并通过十分钟验收的 0.2.8 应用，SHA256：`8ACF0AA665CCB3553CE06802E1E88DB4C8B45B85CACC4D490AC75549076C62F2`。恢复后 Watch 运行／暂停改向／恢复／慢 Timeline 四阶段检查及 pyOCD 再次通过，目标保持 Running；64 KiB 独立回读仍与上述 fixture 哈希一致，服务 owner 已释放。当前源码的 TCP64／512 也重新构建通过；重新构建产生的镜像单独记录，未冒充实际刷入的封存镜像。

新增离线录制复核统计每个字段的首值、末值与变化次数，并要求十个动态叶节点都发生变化。重复采样值和计数器回绕允许通过；“身份标记正确但某字段始终不变”会失败。81 项主机测试通过。初次手动身份复核误用了超过 API 4096 B 上限的读取，收到 `invalid_request`；改为 16 个 4096 B 分片后通过，没有修改服务边界。

对 0.2.8 已完成的十分钟录制重新校验，197303 帧哈希、CRC 与原统计一致。Timeline 为 141145 帧／235.18045 Hz，十个字段各观测到 54449 次变化，在 Timeline 时间窗口内约 90.73 次／秒；Watch 四字段各变化 6001 次。fixture 在主循环中更新字段并执行延时，因此采样频率和目标变量变化频率需要分别记录，不能要求每个相邻采样值不同，也不能把 235 Hz 称为目标程序的更新频率。

原有超期统计保持：Timeline 跳过 459008 个计划时隙，所有帧有预算标记；字段有效位完整、SWD failures／ring_dropped／消费者缺口均为零。RTT 提交字节连续，但开始阶段有一次生产端跳过 21 条记录。离线新鲜度检查没有消除这些已有的性能限制。

## 下一步

先量化每帧实际 SWD 工作、解析与执行器等待，再决定减少 DP SELECT／AP CSW 重复设置或调整指针批次。测量必须覆盖静态、共享和独立深链，保留控制优先级以及所有权／缓存失效规则。仍须分别验收实际 SWCLK、控制长尾、真正电脑重启／静默 TCP 断连及已安装前端；现有短测不代替这些条件。
