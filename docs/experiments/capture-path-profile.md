# 采样耗时分解：先优化板端访问路径

2026-10-15。基于 `daf8d75`，临时固件 `0.2.10-profile` 仅用于诊断，未成为默认版本。普通 0.2.8 → 计时版 → 普通 0.2.8，分别完成三轮对照；测试后设备恢复封存的 0.2.8。汇总、每轮结果与文件哈希见 [机器记录](capture-path-profile.json)。

## 测量方式

沿用同一 STM32F103C8 fixture、CPU0、TCP512、GPIO4/5、电脑 2.4 GHz 热点，请求 SWD 4 MHz，实际 SWCLK 未量测。Timeline 十个 32-bit 变量、叶间隔 64 B、请求 1 ms；同时运行四字段 Watch（100 ms）和 RTT（5 ms）。每个布局采五秒、重复三次，每版 15 轮。通过公开连接服务和真实板端执行，不含已安装 VS Code 界面。

计时只覆盖 Timeline，分为：

- `span`：有效完整帧从开始到采集结束的板端墙钟时间，与帧间计划等待分开。
- `work`：该帧各次执行器采样工作段的耗时之和，包含初始化、解析和 DAP 调用，不包含发送帧、刷新定时器及批次间调度。
- `dap`：内部 DAP_ProcessCommand 访问路径的耗时之和，起点包含设置传输期限，终点在调用返回后。
- `calls`／`turns`：内部 DAP 调用数／有实际采样工作的执行器次数，不是网络往返或物理 SWD 事务数。

只对有效完整帧累加；一条汇总在 STOP 时输出，不在逐帧采集期间打印。所有值均为墙钟时间，包含测量点之间的中断和任务抢占；`dap` 不能当成纯线速传输时间，`span-work` 也不全是任务等待。相邻帧之间的计划等待没有计入 span。

## 测量结果

以下为计时版三轮完整有效帧的加权平均，先求各项总和，再除以总帧数；不是 P50。普通版／计时版的实际采样率对照单列在机器记录中，避免混淆均值、分位数及不同统计窗口。

对独立四级链，约 3.88 ms 的帧内跨度中，DAP 路径约 3.59 ms，工作段之外约 63 us。现有证据支持优先减少板端目标访问成本；增加 TCP 吞吐不能直接消除这部分耗时。但抢占仍包含在访问路径的墙钟时间中，未独立证明这些时间全部花在 GPIO 翻转。

计时本身会改变路径和代码布局。共享二级链接近 1 ms 边界，计时版采样率有下降，不能把本表的小数当作普通固件的无扰动精确分解。普通版在试验前后分别复测，原始三轮全部保留。此试验没有提高采样率，也没有进行计时版完整烧录／调试或十分钟资格验收。

## 下一项实施约束

源码中 word、block、scattered 每次都明确设置 DP SELECT／AP CSW；独立四级链每帧十个调用，重复前置写入有优化空间。优先评估统一执行器内的 MEM-AP 状态复用，先设计并测试以下失效点，再改默认路径：原始 CMSIS-DAP 命令、目标控制屏障、连接／断连、复位、传输异常与取消、所有权变更。不能仅删除前置写入，也不能缓存并固定目标指针的最终物理地址。

仍保留每个执行器工作块最多八个物理读取和控制请求优先。验证必须同时覆盖共享二级临界布局、独立三级／四级链、指针改向、原生 USB、虚拟 USB、RTT 不重复提交及控制长尾。不能用本次帧内占比解释全部控制延迟；网络和服务的控制往返还需单独测量。

复现工具为 [矩阵脚本](capture-profile-harness.py) 和 [诊断补丁](capture-path-profile.patch)。补丁基于 `daf8d75`，默认源码未应用；诊断镜像和刷写收据独立保存在 artifacts/checkpoints/0.2.10-profile，不能与普通 0.2.8 的安装包或验收混用。
