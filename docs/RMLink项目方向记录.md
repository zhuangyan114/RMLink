# RMLink 项目方向记录

## 2026-10-19 方向变更

用户明确决定：不再通过虚拟 USB 支持无线 CMSIS-DAP，只通过 TCP 向 OpenOCD 提供 CMSIS-DAP。停止推进 USB/IP/UDE 挂载及其驱动签名分发路线；原生 USB 有线功能与 RMLink 增强 API、板端采样和缓存烧录保留。实施约束、现有代码状态与待验收项以[当前项目方向](current-direction.md)为准。

以下保留 2026-10-12 的初始讨论与当时状态，不作为当前实现进度或无线兼容承诺。

记录日期：2026-10-12（北京时间，晚间讨论）  
状态：方向记录；尚未完成硬件引脚核对、固件适配或实板验证。

## 1. 项目定位

RMLink 暂定为一个基于 CMSIS-DAP、兼容有线使用、支持无线连接，并针对 Orbit 调试和波形采集优化的调试器。

核心思路：复用现有开源硬件和开源 DAP 固件，把开发重点放在软件适配、无线传输和板端执行能力上。优先做到可复刻、可修改、方便后续维护。

## 2. 今晚明确的方向

| 项目 | 当前方向 |
| --- | --- |
| 名称 | 暂定 RMLink |
| 硬件底座 | 优先使用资料公开、可复刻的 ESP32-S3 开源调试器板 |
| 优先硬件候选 | ylj2000 的“高速无线 DAP 调试器 Lite” |
| 硬件开发方式 | 首版优先复用已有设计，不从零设计 PCB |
| 固件开发方式 | 选用有完整源码的开源 CMSIS-DAP 固件，按底座进行适配 |
| 有线使用 | 保留普通 USB CMSIS-DAP 调试器功能，优先考虑 v2 Bulk/WinUSB |
| 无线使用 | 优先评估电脑通过 Wi-Fi 直接连接 RMLink |
| 配置方式 | 希望通过 USB 配置无线连接参数并保存到调试器 |
| Orbit 优化 | 批量操作、板端执行采样任务、缓存数据后批量回传 |
| 速度目标 | 尽量保持现有体验，并改善 Orbit 采集效率；不预先承诺具体速度 |

蓝牙、CH32 和自定义 2.4 GHz 协议暂作为后续选项，不作为当前首版的优先路线。

## 3. 硬件底座与现有设备

优先硬件候选：

- [高速无线 DAP 调试器 Lite（ESP32-S3，ylj2000）](https://oshwhub.com/ylj2000/dap_hs_esp_open)

原项目描述了 USB 有线模式和双设备无线模式；无线套件由 Host 与 Slave 组成，两端可通过按键切换角色。项目说明列出的主控型号包括 ESP32-S3FN8、ESP32-S3FH4R2，具体复刻版本仍需核对。

用户当前已有一款从“淘宝－ABrobot智能”购买的 S3 调试器，体积较大、有屏蔽罩，外观与上述开源板不同。原项目页面确实将 ABrobot 列为授权销售商，但这不足以证明现有设备与开源板的 PCB、GPIO 和外围电路完全相同。

**最新选择：以开源设计作为 RMLink 的硬件底座。现有 ABrobot 调试器可用于对照和性能基线测试，不默认把它作为最终底座。**

开始固件适配前，需要建立底座的板级配置，至少核对：

- SWDIO、SWCLK、复位、UART 对应的 GPIO。
- 如果存在信号缓冲器，其方向、使能和有效电平。
- USB 接线、进入下载模式的方法、按键和指示灯。
- 主控具体型号、Flash 容量、PSRAM 以及分区配置。

原理图逐脚核对尚未完成。当前不能声称其他项目的现成固件可以直接刷入。

## 4. 固件基础

硬件开源与固件源码公开是两件事。可以使用上述项目的硬件设计，再移植另一套有源码的 DAP 固件；不必以获得原配固件源码为前提。

今晚讨论过的固件候选：

- [hongquan-prog/ESP32-DAPLink](https://github.com/hongquan-prog/ESP32-DAPLink)

该项目基于 ESP32-S3 / ESP-IDF，公开了 USB HID/Bulk DAP、串口和 Wi-Fi USBIP 等实现。它可作为评估对象，但尚未确定为最终基础，也未验证与选定底座的兼容性。

正确的复用方式是“获取源码 → 核对板级连接 → 配置或修改驱动 → 编译 → 实板验证”。GPIO、缓冲器控制和存储配置不一致时，不能把现成的 BIN 当成通用固件。

Wi-Fi USBIP 是候选项目已有的无线方案。Orbit 原生网络连接和自主采样协议仍需要单独设计、实现和验证。

## 5. 连接方式

首版优先评估以下两条路径：

~~~text
有线：
电脑 / Orbit / 其他支持 CMSIS-DAP 的工具
                ↓ USB
              RMLink
                ↓ SWD
              目标 MCU

无线：
电脑上的 Orbit
                ↓ Wi-Fi / IP
              RMLink
                ↓ SWD
              目标 MCU
~~~

无线可以评估 RMLink 自己开热点，或加入电脑热点 / 同一局域网。目标端调试器仍需要供电，无线化的是电脑到调试器之间的通信。

这条直接 Wi-Fi 路径在架构上只需要一块目标端调试器，电脑端不必再插原项目的 Host。Orbit 需要增加对应的网络接入能力。

原项目的无线配对方式不能直接当作普通 Wi-Fi 热点连接方式使用。如果继续保留原来的双设备链路，新固件必须兼容原无线协议，或同时修改两端固件。

USB 配置无线参数、保存配置、再次启动后连接，是希望实现的使用方式；目前尚未实现。

## 6. 群友建议与 Orbit 优化

群友提出的“上位机下发自定义 SWD 序列组合”，可以先理解为：电脑把一组操作打包交给调试器，调试器在本地连续执行，再集中返回结果，以减少一次操作对应一次无线往返的开销。

需要区分两个层次：

1. 标准 CMSIS-DAP 的传输和序列命令，如 DAP_Transfer、DAP_TransferBlock、DAP_SWD_Sequence；后者需核对协议版本和实际实现。DAP_ExecuteCommands、DAP_QueueCommands 则需先通过 DAP_Info 确认 Atomic Commands 能力，并遵守包大小和数量限制。参见 [ARM 序列命令说明](https://arm-software.github.io/CMSIS-DAP/latest/group__DAP__SWD__Sequence.html)和[原子命令说明](https://arm-software.github.io/CMSIS-DAP/latest/group__DAP__atomic__gr.html)。
2. RMLink 的扩展任务，如按周期重复采样、读取多个离散地址、解析指针链、缓存并批量回传数据。这些能力不能默认已有。

对 Orbit，优先考虑让电脑下发采样计划：要读什么、多久读一次、采集多久。调试器本地执行 SWD 读取，为样本记录时间和序号，缓存后批量回传。

实现约束：同一目标只允许一个 SWD 执行者，控制、观察和采样统一调度；USB 与 Wi-Fi 同时可用时，也需要统一管理目标访问。控制操作应能及时打断或暂停后台采样。

Orbit 既有的单目标所有权和控制优先约束沿用先前设计记录；本次没有重新检查当前 Orbit 源码。具体接口、调度和扩展命令格式仍待设计。

## 7. 速度与验证

Wi-Fi 链路带宽、SWD 时钟、固件下载速度和变量采样频率是不同指标。不能用无线标称速率推导实际调试速度。

首轮测试应在同一目标板、同一固件和同一组变量下比较：

- 当前 ABrobot 调试器的有线、无线表现，作为基线。
- RMLink 标准 USB DAP 模式。
- RMLink Wi-Fi 逐请求模式。
- RMLink Wi-Fi 板端批量采样模式。

记录实际读写吞吐、烧录与校验耗时、成功采样频率、控制延迟、丢样和断连情况。比赛场馆等拥挤无线环境也应单独测试。

目前没有 RMLink 实板性能数据。“更快”是设计目标，不能写成已验证结果。

## 8. 建议推进顺序

1. 获取并保存开源底座的原理图、PCB、BOM，确认可复刻版本及 GPIO 映射。
2. 评估固件候选，完成对应板级适配。
3. 跑通标准 USB CMSIS-DAP：识别、连接、读写、复位、烧录与调试。
4. 实现 USB 配置无线参数，以及基础 Wi-Fi 连接。
5. 接入 Orbit，先跑通网络下发命令和结果回传。
6. 增加板端批量执行、定时采样、缓存与流式回传。
7. 与现有调试器比较速度、控制延迟和稳定性，再决定是否继续研究自定义 2.4 GHz 链路。

后续首先要确认的是底座的完整硬件资料和固件源码适配范围。当前阶段以明确方案、减少硬件开发工作、保留可维护性为主。
