# 修复与功能记录

每次修改bug或加新功能（我手动验证通过后）详细记录。

## 记录规范

- 用户明确确认手动验证通过后，写入正式记录。每项修复或功能单独成文，文件名采用 `YYYY-MM-DD-简短主题.md`，日期使用用户确认日期。
- 沿用 Orbit 修复日志的主要字段，详细记录日期、用户确认、问题描述或功能需求、根因或设计依据、修改方案、涉及文件、验证步骤与结果。
- 涉及固件时，记录设备、芯片、版本、构建配置和镜像摘要，便于区分沿用版本号的不同构建。
- 自动化测试、构建、实板验收与用户手动验证分别记录，说明实际覆盖范围及未确认项。
- 原始日志、构建产物与设备数据保存在 `artifacts/`，在记录中注明证据位置。确认后的补充验证按日期追加到原条目中。
- 下方索引按确认日期倒序排列，最新记录放在最上方。
