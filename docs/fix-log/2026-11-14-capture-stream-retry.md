## 问题描述

Timeline 启动失败，提示 `Capture stream failed; close the owner session before reconnecting`。此时 RMLink 控制台仍显示设备通过 Wi-Fi 在线，调试控制和采样数据使用独立连接；设备在线并不代表采样数据流仍在工作。

## 故障证据与根因

现场设备为 `cc68c7a5995c`。2026-11-13 本地 22:54:51 至 22:55:03 的日志显示，板端采样 TCP 重传计时从 5000 ms 增至 10000 ms，重试计数升至 2；随后出现 `send_errors=1`、`last_errno=11`，采样连接关闭，主机报 `ConnectionError: Probe capture stream closed`。这解释了数据流的中断，但没有定位无线丢包发生在哪一端。

阻止再次启动的直接原因在 `Subscriptions.ensure_stream()`：一旦 `self.error` 非空，后续创建订阅就永久拒绝重新绑定数据连接，即使原控制 owner 仍有效。此前只能结束整个调试会话，才能清掉这份失败状态。

## 修改方案

1. 新建订阅时，先检查槽位是否可用；无效的重复创建不触发重连。
2. 需要重建数据流时，取消并等待旧读任务，关闭旧 TCP socket 或 USB bulk stream，通过新 ticket 重新绑定，用新解码器接收数据。
3. 握手失败或启动取消时清理本次连接，保留原错误供查询，允许下一次明确重试。修改旧 `resume` 错误提示，引导调用者删除并重新创建订阅。
4. 保留控制 owner 和递增的服务游标，不自动重放其他旧订阅。清掉旧控制暂停的自动恢复标记；新建 Timeline 仍遵守目标暂停状态。
5. 断流导致的录制失败仍以 `failed` 收尾，不续写旧文件，不把新的采样伪装成连续录制。

这次修复没有修改固件的采样周期、缓存策略、TCP 发送超时或无线参数。
