# 五个三级指针与五个普通变量：1000 Hz 优化

目标：只优化五条独立三级指针链、五个普通 uint32 变量；目标运行中采集，叶子间隔 64 字节。SWD 请求时钟保持 4 MHz，Timeline 请求周期 200 us，Watch 四字段 / 100 ms，RTT / 5 ms。实际采样率与请求频率分开记录。

## 0.2.17 实板基线与失败证据

- 三轮短测，中位数 676.217 Hz，采集跨度 P50 1275 us，采样间隔 P50 1460 us。
- 600 秒验收在 569.555 秒失败，前 387763 个有效 Timeline 样本约 680.751 Hz；不能标为长测通过。
- 全部三路 RML1 应用流：42172536 字节 / 569.554689 秒，即 74044.75 B/s（72.309 KiB/s，0.592358 Mbps）。包含 RML1 帧头，不含本地游标封装、控制连接、TCP/IP、802.11 与重传。
- 第一次异常：请求 18 个 DAP 操作，完成 17 个，WAIT，累计 2 ms 墙钟截止触发。目标写入标记为 false；无 ring 丢帧。这证明了终止条件，尚不能证明最初 WAIT / 抢占的原因。
- 原始文件：`artifacts/logs/mixed-5ptr3-5direct-5k-600.json`、同名 UART 日志；保留失败记录。

## 定位与约束

0.2.18 先增加累计 SWD 事务、WAIT / 错误、CPU 周期、线时钟数、采集 DAP 时间、物理读字数和帧数。通过只读 `80/0B` 与服务 health 返回；不逐样本打印串口。

不得跨帧复用指针或变量值，不改变五条链为共享链，不提高默认 SWD 时钟，不重复执行结果不确定的目标写入。

ARM ADIv5 规定：AP 读结果尚未取回时执行 AP / DP 写，之前结果会丢失。不能通过交错 TAR 写与未完成 AP 读来省略 RDBUFF。

依据：[Arm ADIv5 规范 B4.2.2](https://documentation-service.arm.com/static/622222b2e6f58973271ebc21?token=)。

## 已实施的优化

1. 每帧仍重新读指针和值。测试中五条链互不共享，但每条链的三个节点位于相邻的 12 字节；在 RAM 中有限预读三字，后续节点只有实际指针指向它时才使用缓存。不会据此假定任意指针链相邻，也不预读外设。
2. 每次执行最多八个物理字读取。把预读窗口和已经确定的普通地址合成一个 DAP 命令，相邻地址复用 TAR 自增。这组布局从约 75 次成功 SWD 事务降到约 55 次，仍读取 25 个物理字；初次配置 SELECT/CSW 另计。
3. 非严格实时模式在过期帧结束后立即继续。错过的理想采样时隙在下一帧开始时统计，不再额外向上等待 200 us 网格。每个 Timeline 帧后给低频 Watch/RTT 一个有界执行机会；排队控制请求仍优先。
4. SELECT/CSW 配置可跨连续采集帧复用；外部命令、控制屏障、连接关闭与任何失败使其失效。TAR、变量值及解析出的指针不跨帧复用。
5. 帧内地址查询使用有界哈希表，CRC 使用同一 IEEE 多项式的 ROM 实现。4 MHz 使用原 SWD 内核的常量延时分支，仅精确请求 4 MHz 时启用；其他时钟保留通用路径。
6. SWDIO 保留专用 GPIO 的数据路由，初始化时明确让 GPIO_ENABLE 控制输出使能。换向只开关输出，省去 HAL 每次拆除和恢复矩阵路由的额外写入；关闭调试接口仍完整释放引脚。
7. RTT 每轮仍重新校验签名、通道数、buffer/size、WrOff/RdOff；省去未使用的 name、flags 和 down_count 共三个字。没有使用过期的 RTT 布局。
8. 仅 RAM/Flash 读取因墙钟截止发生部分响应时，丢弃该响应，先让出执行器，再重新配置 SELECT/CSW/TAR，最多重试一次。显式 Abort、NO_ACK、FAULT、格式异常和结果未知的目标写入不走此恢复。RTT RdOff 未知写入仍通过描述符对账处理。

主机 C 模型覆盖 25 字实际组合、非相邻节点回退、32 个四级链的 160 字上限、根节点变化、控制抢占、分次重试和未知写入不重放。预读的提速依赖空间局部性；各级节点全部分散时可能多读 RAM，不能将本组收益推广到任意布局。

## 72 MHz 测试基线

用户于 2026-10-16 确认：后续 STM32F103 测试默认 72 MHz，SWD 仍为 4 MHz。

先以 HSE 直接作为系统时钟，使用 DWT/主机单调时钟估测约 7.98 MHz，识别这块板的 8 MHz 外部晶振，再启用 PLL×9。`RCC_CFGR=001d840a`：SYSCLK/HCLK/APB2=72 MHz、APB1=36 MHz、ADC=12 MHz，Flash 两等待周期并启用预取；HSI 保持开启。配置依据 [ST RM0008](https://www.st.com/resource/en/reference_manual/rm0008-stm32f101xx-stm32f102xx-stm32f103xx-stm32f105xx-and-stm32f107xx-advanced-armbased-32bit-microcontrollers-stmicroelectronics.pdf)。DWT/主机时间是估测，不是外部频率计。

测试固件启动时配置以上时钟；振荡器失败时回退 HSI。性能脚本读取 RCC，发现回退或分频不匹配则拒绝运行。生产循环的忙等待由 8000 次改为 72000 次，防止 RTT 生产速率仅因主频变更暴增；这不是精确定时，实际 RTT 生产率另行记录。

新 64 KiB 镜像 SHA256：`ed4a0cd5b5e76d9696ed1f03303cd819f00229e93b047a06efed7caf86f4ffc0`。旧镜像及 ELF 保存在 `artifacts/checkpoints/fixture-8mhz/`。新程序已由 0.2.24 板端缓存烧录完成全片回读比较，复位后 RCC 校验通过。

每轮测量前，测试脚本明确丢弃 RTT 中测量前积压的数据并记录字节数，避免将前一次会话关闭期间的目标端非阻塞跳过计入本轮。公开订阅接口不会自动丢弃 RTT 数据。

## 0.2.25 网络稳定性改动

原采样流启用 NODELAY，取到数据后立即发送，但取空时已有 10 ms 轮询等待，实际上也会形成批次；不能据此断言每帧对应一个 TCP/Wi-Fi 包。字节速率较低并不表示包处理与内存压力也低。0.2.25 增加目标 2 ms 的合包定时，控制连接仍独立且保持 NODELAY；定时调度、取空等待、TCP 排队另计，不能将 2 ms 当作端到端延迟上限。不重放任何目标写入。

板端记录发送/接收失败的 errno、剩余字节与内部 RAM，并在采样流关闭时记录 batch/bytes；主机保留物理连接错误和命令 ID，重连不清除日志。详细统计默认关闭；批次时间、物理读字数和失败诊断始终保留。新的长测须独立通过后再更新最终验收结论。

## 网络发送长尾定位与 0.2.28

0.2.25 两次 900 秒请求分别在 37.3 秒、47.2 秒失败：板端 `send()` 返回 EAGAIN（2 秒发送超时），主机控制请求随后超时。后一次已将 Windows 主机名解析改为异步，并开启事件循环停顿／栈监测，未记录到主机事件循环长停顿；异步解析并未消除此失败。

0.2.26 通过 ESP-IDF 的能力分配器将 Wi-Fi/lwIP 缓冲优先放到 PSRAM，保留普通 malloc 与 USB DMA 的内部 RAM 配置。内部 RAM 最低空闲提高到约 111 KiB，但第三轮短测仍丢 2552 个 Timeline 样本；内存压力得到缓解，发送停顿尚未解决。

0.2.27 将发送任务固定在 CPU1，增加合包定时唤醒与 `send()` 分别计时。三轮短测虽通过，定时唤醒最长仅 740 us，`send()` 却最长等待 309521 us，说明此时长尾主要发生在网络发送路径，而非合包任务未获调度。未捕获空口数据，不能进一步断言是无线重传、ACK 延迟还是 lwIP 排队的哪一项。

0.2.28 把 TCP 发送缓冲从 5744 B 提到 32768 B，仍由上述能力分配器分配；仅连续样本数据流启用 Nagle，让 TCP 聚合完整报文段，控制连接保留 NODELAY。两项同时变更，实测不能分离各自贡献。三轮短测 1099.448 / 1099.959 / 1098.172 Hz，全三路正常、无 ring 丢弃；发送最长等待降到 1039 us，唤醒最长 680 us，内部 RAM 最低 91176 B。

这些是本机热点、此设备和这组字段下的测量，尚不能保证其他网络环境。数据流聚合可能影响到达延迟，采样时间戳仍来自板端；控制连接未增加聚合等待。

### 吞吐和结果口径

0.2.28 三轮短测的全部 RML1 应用流速率中位为 113365 B/s（110.71 KiB/s、0.907 Mbps）。包含 Timeline、Watch、RTT 的 RML1 帧头；不含本地事件 API 包装、控制 TCP、TCP/IP、802.11 和重传。因此它不是空口带宽占用率。此前连续 TCP 有效字节速率约 0.6 MB/s，二者不能将 bit/s 与 byte/s 混用。

每个三级指针变量需要三次解引用和一次叶子值读取；五条链加五个直接变量仍是每帧 25 个物理字。减少的是事务与调度开销，没有少读指针或把旧值冒充新采样。短测 DAP 路径约占总墙钟 86%，包括抢占，不能当作纯电气总线时间。采集吞吐主要受 SWD 事务路径约束；TCP 偶发长尾是独立的连续传输风险，不能因为字节速率低而排除它。

请求 5000 Hz 时，约 1100 Hz 的实际帧率仍会跳过大量理想时隙，并记录 `deadline_missed`、序号跳号和预算超期；这些不等于已采集样本在网络中丢失。板端 `ring_dropped`、实时消费者缺口、CRC／字段有效位、录制完整性分别验收。主机有界历史的正常淘汰 `host_history_evicted`（兼容旧名 `host_dropped`）也不能与实时消费者丢帧混为一谈。

本组指针节点的位置不变，十个叶子值持续变化，约 62.5 次/秒的 fixture 生产速率与约 1100 次/秒的读取速率分别记录。根节点改向与非相邻节点回退已由模型覆盖，本轮不将其称为真实目标上的动态指针长测。

证据：`mixed-focus-0228-72.json`、`mixed-72-0228-short-uart.log`，以及各版失败 JSON／UART，均在 `artifacts/logs/`。失败文件不覆盖。

## 最终 0.2.28 验收

同一字段组合、72 MHz F103、4 MHz SWD、200 us请求周期，Watch四字段/100 ms和RTT/5 ms共存。连续900.015秒完成，实时Timeline平均 **1108.679 Hz**；无数据无效、板端ring丢弃、采集IO失败或实时消费者缺口。十个动态叶子各观察到56252次变化；RTT完整记录56265条，生产端跳过和字节缺口均0。RTT轮询的一个期限跳过仍保留，不能称所有截止期限均满足。

独立录制1063102帧，其中Timeline997857、Watch9000、RTT56245。录制开启／停止窗口与实时观察窗口略有差异。全文件重新解析CRC、字段有效位、值身份、RTT校验及SHA256一致：`5dbe4ab28bd82188f434e40135c8d02f80bad513a89f058c3ae46c310a67aef7`。兼容字段`invalid_samples`包含预算超期，本轮`invalid_data_samples=0`；997857个Timeline预算超期明确保留。

全录制的Timeline间隔P50/P95/P99/最大为 **884/1086/1231/2518 us**；帧内采集跨度为 **812/987/1122/2505 us**。这是平均吞吐达到1000 Hz，不是严格每1 ms完成一帧。采集DAP路径占相应板端墙钟约86.90%，含抢占；本轮逐事务SWD统计关闭，不能把冻结的零计数解释为没有发生SWD事务。

录制中的全部RML1帧共101391832字节，除以900.042482秒的板端时间跨度，约 **112652 B/s =110.01 KiB/s =0.901 Mbps**；不是空口吞吐或无线占用率。长测发送最长仍为 **377010 us**，合包唤醒最长1258 us，内部RAM最低80620 B；本轮缓存承接住了发送停顿，但根因和更长持续时间／其他热点尚未穷尽。

同版标准无线虚拟USB的OpenOCD完成64 KiB烧录、校验、软件复位，无Error行，功能计时6.550秒；不据单次计时推导烧录加速。硬件断点、软件断点、单步、DWT、FAULT恢复、异步Abort及有界截止通过，物理NRST因缺线排除。随后原生USB64／虚拟USB512分别完整回读64 KiB，与72 MHz fixture一致，目标保持Running、RCC配置正确。主机112项测试、采集／核心／缓存烧录模型及TCP64/512构建通过；安装的VS Code界面、Keil/IAR和正式驱动签名不在本轮结论内。

最终日志为`mixed-72-0228-900.json`、`mixed-72-0228-900-timing.json`、`accept-virtual-usb-0228.json`、`standard-usb-0228.json`。二进制与配置身份、完整记录SHA及限制见[mixed-subscription-checkpoint-0228.json](mixed-subscription-checkpoint-0228.json)。

## 复现本组测试

在项目根目录使用 ESP-IDF 的 Python 环境，设备加入电脑 2.4 GHz 热点、连接服务运行、目标运行 72 MHz fixture，并释放其他调试会话。测试会重写 fixture 的指针测试 RAM 和 RTT 读偏移；不用于其他应用固件。

```powershell
.\scripts\Build-Firmware.ps1 -TargetProfile -TcpPacketSize 512 -ExecutorCore 0 -ImageCachePsram
python scripts/benchmark_mixed_focus.py --seconds 15 --repetitions 3 --output artifacts/logs/mixed-short-new.json
python scripts/verify_subscription_soak.py --pointer-depth 3 --independent --direct-fields 5 --period-us 200 --seconds 900 --output artifacts/logs/mixed-soak-new.json
python scripts/verify_standard_usb_read.py --output artifacts/logs/standard-usb-new.json
```

短测脚本固定为本组字段，始终与 Watch/RTT 共存。可在独立的一次同组测试中加 `--profile-swd` 诊断，但正常性能验收关闭逐事务统计。UART 另开进程被动录制，刷写前释放 COM13；输出名必须新建，以免覆盖失败证据。
