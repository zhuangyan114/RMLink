# 0.2.7 网络恢复修正与验收

2026-10-15。当前开发板运行固件 0.2.7；连接服务和 SDK 仍为 0.2.6，协议未改变。0.2.6 的固件、完整检查点与开发包保留，提交为 `9fd20dab37017537d6daf1620b6acd5e77609801`。本轮没有替换 Windows 内核驱动、修改热点参数或安装 VS Code 扩展。

## 触发与源码依据

电脑重启并恢复热点后，ESP32 通过原生 USB 报告 STA 在线、地址变为 192.168.137.170，信号约 −16 dBm；Windows 能解析设备名，但 TCP 入口连接超时，服务停留在旧地址。仅发送 USB 厂商命令 80/05 让 STA 重连后，自动发现／TCP／虚拟 USB 恢复；没有重刷或复位 STM32。

源码检查发现，旧 TCP 服务串行处理一个客户端，只检查 s_up 的当前值。它既未启用 TCP keepalive，也未记录短暂断开／重新获得 IP 的历史。静默失效的旧连接可能长期占用接收循环；两次任务轮询之间的 down/up 也可能被当前布尔值掩盖。这是与观测相符的恢复缺口，尚未通过完整电脑重启复现并排除其他因素，不能将推断写成已经确定的唯一根因。

## 已实施

- 接受 TCP 连接后启用 SO_KEEPALIVE：空闲 5 秒开始探测，间隔 2 秒、3 次探测。探测由 TCP 栈完成，不添加 SWD 操作，也不按空闲时间踢掉仍能应答的调试客户端；配置失败明确拒绝该连接。
- STA 断开或获得 IP 时递增网络 generation。监听和客户端保留创建时的 generation；即使 s_up 已重新变成 true，旧连接也退出。
- TX 工作任务在 generation 失效时关闭 socket、唤醒 RX；收到完整请求后再次核对 generation，旧连接不继续提交请求。
- 原来的目标取消、FIFO 清理屏障和回调上下文回收顺序保留。仅关闭 TCP 对应会话，不释放另一个 USB owner，不复位 MCU，不重放写入或旧订阅。
- 打包工具拒绝固件／SDK 版本不一致和覆盖已有版本包。0.2.7 候选不会被误打进已验收的 0.2.6 包。

## 本轮实际结果

CPU0／TCP64、TCP512 构建通过。实际刷入 TCP512，应用 SHA256 为 `4F2954554183BEE0078D25A9D29590BC587126086CC5A1B4D6145AE2EF049875`；sdkconfig 为 `0401E92008615BF8F8CA8E39649894F3BDA799504DE339207112F1BA566B2211`。请求 SWD 4 MHz，未仪表量测。

直接 TCP 持有 SWD owner、完全不发送 DAP 命令约 20 秒后，CPUID 读取及原 owner 保留检查通过，外部 USB 仍不能抢占。随后交换占用方式：USB 持有同一目标，TCP 保持连接，再通过 USB 80/05 仅断开 STA。五轮重新连接均通过，TCP 重新可用约 1.63–3.57 秒；期间 USB CPUID 读取累计 137 次、最大一次约 10.40 ms，USB owner 始终保留，目标 counter 增长，ESP32 uptime 未归零。

首次直接测试脚本仅等待旧 socket 的 EOF，未主动发送数据；关闭通知在 Wi-Fi 断开期间可能未到达电脑，因此脚本在新连接检查前超时。修正为网络回来后向旧 socket 发送一次只读 DAP_Info，明确观察旧 TCP 失效，再检查新连接；不重放目标读写。首次失败报告与修正后五轮报告分别保留。

连接服务中的真实断连检查通过：旧会话约 3033.57 ms 返回 Lost，旧实时录制以 session_closed 封存 520 帧；自动发现／虚拟设备约 5914.46 ms 恢复。旧租约不能复活，旧订阅不自动重放，旧文件哈希不再变化，显式新建订阅正常，最终 owner 为空。这只是一轮服务路径测量，不能与前述不经服务的 TCP 恢复计时混用。

同一候选固件的标准虚拟 USB 全流程通过：64 KiB 编程／校验 6025.72 ms，完整回读、哈希、选项字节、寄存器／RAM、断点／单步、DWT、软件复位、异常及取消检查通过，fixture 保留且运行。pyOCD 0.45.1 经同一虚拟设备暂停／读取 PC／继续通过。本轮 6.03 秒与 0.2.6 的 12.40 秒均保留为当时条件下的功能计时，没有隔离网络波动，不能归因于此次保活修正。

无线三订阅严格录制通过，2029 帧、gaps=0、invalid_samples=0；RTT 重建 50 次通过。慢消费者的独立文件有两次序号缺口，与板端 deadline_missed=2 一致，SWD failures 与 ring_dropped=0；不能把本轮慢消费者录制写成零超期。原生 USB 三订阅回归也通过，结束后恢复 Wi-Fi 选择。

## 尚未验证

没有再次重启电脑，也没有注入能阻断 TCP 所有报文的静默半断连。因此，保活参数的静默失联检测时长、真正电脑重启后全自动恢复，仍需另验；不把按参数推算的时间当成实测值。0.2.6 的十分钟指针测试不能充作本镜像的十分钟结果。

一次 Orbit 子进程曾以 0xC0000409 退出，仍未确定原因。本轮仅补充可选的 Node fatal report（排除环境变量）和请求阶段记录，未修改 Orbit 源码；矩阵／共享三级指针交替共 20 次短启动、三订阅与暂停／继续检查全部通过，未生成 fatal report。这未复现旧退出，不能证明已修复。未达到的持续 1 kHz、控制尾延迟、已安装 VS Code 界面、物理 NRST、正式签名及其他前端／目标仍按原状态保留。
