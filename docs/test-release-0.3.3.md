# RMLink 0.3.3 USB 连续回传测试

本页记录 Windows 原生 USB 连续回传与请求 5000 Hz 的实板测试。最终镜像、持续采集、兼容回退、升降级、公开下载安装和原程序恢复均已完成；纯回传测速和实际 SWD 采集分别验收。

## 镜像与实现

- 固件、客户端和连接服务为 **0.3.3**，SDK 仍为 **0.2.8**。
- 经过实板测试的应用大小为 **892528 B**；SHA256 为 `f3346b14a491a7e56ac913b4233f892da27996c6c54d197669c5e1dc1822c38c`。
- 运行 ELF SHA256 为 `e089cb5eec8f7781e685d4c146aa07ee1ba8742894ac5405c51bbd72a5dd61f3`，硬件 profile 为 `16445f574834cf7b`，GPIO4／5／6、PSRAM、TCP512／core0／streamdiag／video。
- alternate 0 保留标准 CMSIS-DAP；alternate 1 为同一 owner 增加独立 Bulk IN。设备从既有 2 MiB PSRAM Timeline 环取完成记录，使用两个 4 KiB 内部 RAM 暂存区，主机每次读 8 KiB。
- 旧固件和端点不足的 CDC＋MSC 组合保留 USB_PULL；没有改写第三方库、内核驱动或 SWD 频率。

## 已完成

- 同一 ESP32-S3、原生 USB、WinUSB 和电脑上，旧请求／响应流水基线中位数 272.96 KiB/s。
- 最终镜像独立连续 Bulk 通道三轮各 8 MiB，**8.9932／8.9994／8.9964 Mbit/s**，中位数 **8.9964 Mbit/s、1.1245 MB/s**，约为理想 Bulk 有效载荷上限的 **92.48%**。每字节及绝对 4 KiB 块序号检查无误；48 次并发控制查询，中位数约 0.22 ms，最大 **0.4392 ms**。
- 单次 **64 MiB** 连续回传实际 **59.7706 秒、8.9822 Mbit/s**，8192 次主机读取均校验内容与块序号；128 次并发控制查询中位数 **0.2320 ms**、最大 **0.4869 ms**。测速时空闲连接服务临时改走 Wi-Fi，避免两个读取者消费同一 DAP 控制端点，结束后恢复 USB 偏好。
- 最终镜像 10 字段、1 ms 周期的 PSRAM 背压测试：暂停主机读取 2 秒，保留 **2028 帧**，恢复阶段接收 **5030 帧**，共检查 **7031 帧**。环形缓冲丢帧与 SWD 失败均为零，实际记录缓存容量 **2113536 B**。
- 安装后的 0.3.3 客户端 USB 15 秒短测：Timeline 约 1000 Hz，Watch、RTT、三层独立指针链、5 个直接字段和录制同时工作，consumer gap 为零。
- 原 STM32 64 KiB 程序已重新备份，SHA256 为 `eeb3aebb22d7b5967282934a4b0ae732c083da67753c197add68d54d718b9360`；选项字节已留存。测试期间使用无外设输出的 F103 fixture，最终已恢复原程序。

公开发布与安装结果见文末。

## 最终 USB 持续采集

安装后的 0.3.3 服务使用最终镜像、原生 USB 实际采集 **900.0046 秒**。STM32 fixture 为 72 MHz，请求 SWD 4 MHz；五条独立三级指针链加五个直接字段、字段间隔 64 B，与四字段 10 Hz Watch 和 5 ms RTT 轮询共存。Timeline 实测 **999.9933 Hz**；Watch 约 10 Hz，RTT 约 62.49 条记录／秒。

原始录制 **965239 帧／103579924 B**，停止后独立复核 SHA256、逐帧 CRC、序号、字段身份、十字段动态变化及 RTT 字节连续性通过。文件 SHA256 为 `c37e0f7e8a757044dcaaf673b4becac2122d866e9bca78db130a64ce1c2c01f1`。无无效数据、板端缓存丢弃、消费者缺口、RTT 字节缺口或新增 SWD I/O 失败。

本轮采用非严格实时模式：**6 次采样期限跳过、590 帧超预算标志**仍保留，不能称为严格无损／无抖动 1 kHz。末尾 8192 个间隔窗口 P50／P99 为 1000／1073 µs，不代表全程全局分位数。服务的有限历史队列正常淘汰旧数据，独立录制不依赖该历史队列，`host_history_evicted` 不等于消费者丢失。

前后内部 RAM free 均为 108568 B、PSRAM free 均为 6159528 B。读取故障恢复计数均为 12 次尝试／12 次恢复，来自此前受控注入，长测本身的恢复增量为零；原始 I/O 失败计数也保持 12。因此本轮通过没有掩盖新发生的错误，但仍不能推断布线的物理根因已消除。

## 保留的失败记录

首轮复杂 USB 1 kHz 持续测试在 182.902 秒失败。此前 Timeline 为 999.9999 Hz，无序号缺口、无 consumer gap、无环形缓冲丢弃；随后出现无效样本和 SWD FAULT。停止后读取 DP CTRL/STAT 为 `0xf0000080`，包含 WDATAERR。重新初始化后核心仍运行、72 MHz 时钟及 4 KiB 指针区内容未变。WDATAERR 表示 SWD 写数据阶段错误或已接收写入被丢弃，见 [Arm 定义](https://documentation-service.arm.com/static/5f36a71560a93e65927c7dcb)；目前不能据此证明是具体接线、供电或软件时序原因，也不把该次运行列为稳定性通过。

最终候选补充 USB 完成结果／长度检查、取消时的读线程回收和设备停流检查。带绝对 4 KiB 块序号的三轮 8 MiB 逐字节测速中位数 **8.9981 Mbit/s**，零错序／内容错误，控制响应最大约 **0.29 ms**。20 次中途取消、阻塞读取取消约 **7.3 ms**、无效 ticket／重放拒绝和进程异常退出后的恢复均通过。最终候选的持续采样另行记录，不以这些修复推断 SWD WDATAERR 已消除。

第二轮候选也在约 625 秒出现同类读取 FAULT，串口保存了 `count=1/14, status=0x04, target_write=0` 及后续失败。这促使增加专门的只读恢复，而不是宣告 4 MHz 链路无错误。模型覆盖部分读取后的让出执行器、恢复耗尽、500 µs 上限、STICKYERR 不恢复和已完成写入不重放。实板通过 DP SELECT 错误校验位，验证 10 次采集、内存读取和核心状态读取共 **12/12 次自动恢复**，耗尽与未知写入重放均为零，目标仍运行、完整 Flash 及选项字节未变。安装后的恢复计数健康接口已接通，最终长测结果见上文。

恢复只接受单独的 WDATAERR，每帧或 RTT 只读阶段最多一次，总诊断／清除预算 500 µs；重新建立 SELECT／CSW／TAR 后读取，不重放实际目标写入。原始 I/O 失败计数仍保留，因此订阅没有 fatal failure 不等于 SWD 从未出错。最初两轮失败仍是本次测试结果的一部分。

- **200 项 Python 主机测试通过**，包括分片合并、独立数据通道不持有目标锁、读线程取消回收、打开流期间取消、部分超时、停止通知、健康快照解码及 owner 下的只读诊断。追加覆盖不同字段数量的内容／动态检查、样本编码流量计算，以及测速不打断已有 owner、异常时恢复连接偏好。
- C 协议 64／512 字节两档各 20000 组随机报文、采集及只读错误恢复模型、两档缓存烧录模型和 **24576 条 SWD 位轨迹**检查通过；Node SDK 单元测试 7 项通过。
- 最新冻结 Windows 客户端使用隔离未配对状态完成 **10 步验收**，包括并发启动、重复启动、查询、驱动／热点诊断、秘密脱敏和退出；没有改动现场配对或目标 owner。
- [GitHub Linux CI 39181445979](https://github.com/zhuangyan114/RMLink/actions/runs/39181445979) 在恢复实现提交 `b764455` 上通过 safe、target、target-psram 三种配置构建、OTA 镜像和清单检查。额外板型只做编译，没有实板验收；CI 不自动覆盖经过实板测试的发布资产。
- 本地 CDC＋MSC＋DAP 组合配置增量编译通过，该配置回退 USB_PULL；没有将其编译结果当作新独立端点的实板通过。

最终镜像的原生 USB 与虚拟 USB／Wi-Fi 均通过标准 OpenOCD 完整 64 KiB 烧录、校验，以及独立完整回读、RAM 跨 1 KiB 边界、寄存器、暂停／继续、FPB／软件断点、单步、DWT 和软件复位检查。此次 OpenOCD 烧录／验证分别为 3852.66／4208.16 ms，仅记录功能计时；物理 NRST 不在通过范围。

pyOCD 分别按物理 `50787D15A924` 和虚拟 `RM50787D15A924` 精确序列号识别，CPUID、暂停、读 PC、继续通过；Node SDK 批量满包及身份校验、C SDK 目标读取也通过。最新镜像 20 次中途取消、无效／重放 ticket 拒绝、阻塞读取取消 **7.74 ms**、进程异常退出后恢复通过。Wi-Fi 另以相同复杂字段布局短测 30 秒，约 999.24 Hz，保留期限跳过／超预算，无板端丢弃或无效样本。

## 追加：请求 5000 Hz 的实际工况

用户追加要求后，将本轮请求周期设为 **200 µs／5000 Hz**。固件和公共 SDK 原本已允许这一上限，没有提高 SWD 时钟，也没有通过重复同一个变量凑字段数。以下是实板动态变量、Watch 与 RTT 共存的结果；不包含实际 RoboMaster 应用或已安装 Orbit 界面的验收。

| 布局 | 时长 | Timeline 实测 | 结果 |
|---|---:|---:|---|
| 五条独立三级指针＋五个直接变量 | 60 s | 1142.99 Hz | 数据有效，无缓存丢弃／消费者缺口；232096 次序号跳过，所有 Timeline 帧超 200 µs 预算 |
| 十个直接变量，地址间隔 64 B | 60 s | 2245.64 Hz | 数据有效，无缓存丢弃／消费者缺口；165828 次序号跳过，所有 Timeline 帧超预算 |
| 单个动态变量 | 60 s | 4998.45 Hz | 全部订阅的 RML1 样本流 2.4480 Mbit/s；93 次期限跳过、15 帧超预算，无无效／缓存丢弃 |
| 四个直接变量，地址间隔 64 B | 300 s | 4902.62 Hz | RML1 样本流 2.8737 Mbit/s；无无效／缓存丢弃／消费者缺口，保留调度跳过 |

四变量实测 300.0249 秒，完整录制 **1493055 帧／125716668 B**，独立 SHA256、CRC、字段身份、动态变化和 RTT 连续性检查通过。文件 SHA256 为 `889777884be1ce7921d044b268df7c991e32c104b5ebad644ff5c220714dc88e`；录制窗口有 **29018 次序号跳过、126934 帧超预算**，无无效字段。窗口不同的实时统计为 29229 次序号跳过／126980 帧超预算，两者分别保留。四变量本身的数据量约 **0.6275 Mbit/s**，其余样本流量含 RML1 记录头、Watch 和 RTT。

超过执行预算时，探针只产生实际完成的样本并记录期限跳过；请求 5000 Hz 不表示已经实现所有布局的 5000 Hz。`encodedPayloadMbps` 按探针时间戳窗口统计 RML1 记录，包含记录头，排除 USB 事务和控制开销；变量本身的数据率还需按字段数乘 4 B 单独计算。单变量 60 秒的值实际变化 3755 次，读取频率与约 62.5 Hz 的 fixture 更新频率分开记录，不把重复采样算作每秒 5000 个不同新值。

在保持 4 MHz SWD 的这些布局中，多变量先受 SWD 访问／执行预算限制，最高观察到的实际编码流约 2.874 Mbit/s，低于纯 USB 约 9 Mbit/s 的已测容量。没有据此继续提高 SWD；更高频率按用户计划等 PCB 完成后验证。

## OTA 兼容与目标恢复

安装后的 0.3.3 客户端经原生 USB 将探针真实降至已验收的 0.3.2，确认旧 ELF 与 VALID。旧固件采集 feature word 为 1023，不含独立 USB 流的 bit 1024；新客户端自动采用 USB_PULL，复杂十变量、Watch、RTT 共存以 100 Hz 请求采集 10 秒，录制独立校验通过，新的只读恢复诊断子快照明确不支持。

随后经 Wi-Fi OTA 升回本页指定的最终 0.3.3，设备返回匹配 ELF 和 `boot_confirmed`／VALID。整轮没有重刷 bootloader、分区表或 NVS，原 Wi-Fi 参数保留。

完成全部 fixture 测试后，使用缓存烧录接口恢复开始时备份的 STM32 原 64 KiB 程序；板端与主机校验通过。关闭 API 会话后，再经独立原生 USB／标准 CMSIS-DAP 完整回读，逐字节一致，SHA256 为本页原程序摘要；选项字节与最初备份相同，核心 **Running**。最终恢复 Wi-Fi 承载、无目标 owner、未挂载虚拟 USB。

## 条件和限制

本机 Windows，DOIT ESP32-S3 开发板，16 MiB Flash、8 MiB Octal PSRAM，原生 USB VID/PID 303A:1002；STM32F103C8 通过 GPIO4 SWDIO、GPIO5 SWCLK、GND 接入。请求 SWD 4 MHz，没有提高到 8 MHz，没有测量实际 SWCLK、目标电压或物理 NRST。

12 Mbit/s 是 USB 物理信号速率，标准 Bulk 有效载荷理想上限约 9.728 Mbit/s；不能用 12 Mbit/s 作为应用数据的通过阈值。纯 PSRAM 回传不代表 SWD 能以同样数据速率采集任意指针链。实现、兼容回退与复现方式见 [USB 连续回传](usb-throughput.md)。

发布仅使用标注测试的 Pre-release，不覆盖 0.3.2 已验收资产。第三方库、驱动签名、Windows 启动设置、Wi-Fi 凭据和目标选项字节均不属于本次修改范围。
