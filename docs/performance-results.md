# 提速实现与实板结果

日期：2026-10-14。当前运行固件 **0.1.6**、连接服务 **0.1.4**，TCP / 无线虚拟 USB 容量 **512 字节**，原生 USB 保留 **64 字节**，队列仍为 8 包。默认聚合等待窗口为 0；本次烧录验收均请求 2 MHz。完整计划见 [performance-plan.md](performance-plan.md)，机器可读结果见 [performance-results.json](performance-results.json)。

## 已实现的改动

- 逐请求访问只在调用起点和 MEM-AP 1 KiB 边界重设 TAR；流水线每包把 TAR 与读写组合进标准 DAP_Transfer，独立携带地址。前一包部分完成后，后续包不会错位；响应数量、完成数量和 ACK 均检查，未知完成状态的写入不重放。
- TCP / 共享核心支持 64、128、256、512 四档；DAP_Info 和定制状态按当前传输返回真实容量。USB / TCP / SDK / API 的缓冲、声明和边界联动，保留同一个 SWD 执行器及整段会话所有权。
- 连接服务、发现校验、WinUSB 工具和 Node SDK 自动协商容量。HTTP 请求可容纳 8 个完整 512 字节包的 hex 编码及 JSON 开销，仍逐包检查；虚拟端点物理最大包保持 64，单个 URB 可承载较大的逻辑包。
- 服务先检查原始容量，再按已知命令格式去掉尾部零填充；真实写入零值、匹配参数、序列数据、未知命令和非零尾部均保留。固件继续校验命令和目标所有权。
- 增加容量验收、相同会话的内存块预算交替比较、请求时钟扫描；Flash 写入验收的日志按运行目录保存，不覆盖旧结果。

原生 USB 的多包组装和发送终止仍待实现，因此没有给物理 USB 虚报 512 容量。标准 Atomic / SWO / JTAG / HID 及板端采样能力未增加。

## 同会话对照

同一固件 0.1.6、服务 0.1.4、目标原程序、512 容量的无线虚拟 USB、请求 2 MHz，交替使用 64 / 512 字节的内存块预算，各五次完整读 64 KiB。两者都使用当前安全的独立地址算法；小预算仍运行在已协商的 512 传输上，这不是两次固件刷写的 A/B 实验。

| 内存块预算 | 中位耗时 | 中位吞吐 | DAP 命令 | 批次 |
| --- | --- | --- | --- | --- |
| 64 字节 | 6293.200 ms | 10.170 KiB/s | 1152 | 144 |
| 512 字节 | 2450.654 ms | 26.115 KiB/s | 192 | 24 |

该受控比较约 **2.57 倍**；全部读取匹配原备份，测试前后核心运行状态相同、owner 释放。数据在 artifacts/logs/speed-packets-20261014/512/virtual-interleaved-64-512.json。

不同时间窗口的容量扫描也各做五次：64 / 128 / 256 / 512 档中位耗时为 9135.529 / 5659.106 / 3551.735 / 2550.673 ms。早期 64 基线同时有固件构建负载，且无线波动明显，不能把该跨时段比值当作稳定收益。原始数据均保留，最终优先引用同会话交替结果。

## 烧录与调试

每档扩容都编译、刷写、捕获启动与入网日志；每档均通过原生 USB64 / 虚拟 USB / API 的完整与短响应、8 包序列、超容量拒绝、跨 1 KiB 边界只读检查，WinUSB 50 / 100 / 500 ms 空读取消以及 pyOCD 0.45.1。

| 路径 / 版本 | 64 KiB 擦除 / 烧录 / 校验 / 复位 | 日志 Error 行 |
| --- | --- | --- |
| 历史虚拟 USB，固件 0.1.5 / 服务 0.1.2 | 13222.01 ms | 0 |
| 虚拟 USB128，固件 0.1.6 / 服务 0.1.3 | 11065.67 ms | 0 |
| 虚拟 USB256，同上 | 10628.52 ms | 0 |

| 直接 OpenOCD TCP512，Windows 兼容模式 | 39914.81 ms | 128 |

上述是每次功能验收的全流程计时，包含发现、连接和目标 Flash 操作，不是五次性能中位数。直接 TCP 的退出码和独立数据核对通过，但旧 Windows OpenOCD TCP 后端仍报 peek_socket / header 错误，需 min_timeout / quirk 兼容设置；该路径没有达到无错误兼容验收。现有调试软件优先通过虚拟 USB Bulk 接入。

最终虚拟 USB 验收包括独立全 Flash 回读、3072 字节跨边界 RAM 写读、暂停 / 继续、寄存器、FPB / 软件断点、单步、DWT、SYSRESETREQ、FAULT 恢复、SWD_Sequence、异步 Abort 和 1 秒执行期限。原生 USB / 直接 TCP 也完成同一套三线调试检查。每次烧录后恢复原 64 KiB，完整 SHA256 为 **75bcca6e52d436f377542beb94629ef101d153e214ef085b6af7893d40b347ff**，选项字节未变，核心运行。

服务 0.1.4 的 API / 虚拟 USB 互斥、连接前时钟约束、8 个完整 512 字节 Node SDK 请求及 STA 断连恢复通过。最终自动重新挂载约 4781.61 ms，旧租约保持失效，新会话读 CPUID 正确，owner 释放；重新挂载后空读取消和 pyOCD 再连接也通过。这是 USB 命令断开 RMLink STA 的测试，电脑热点未关闭。

## 传输和时钟

当前仅 ESP32 / PC 的测试，RSSI 为 -9 dBm：300 个诊断 RTT 样本，USB64 中位 0.1929 ms / P95 0.2525 ms，TCP512 中位 5.0636 ms / P95 55.7075 ms。绕过 DAP 的原始 TCP 64 字节 echo 中位 3.2086 ms / P95 48.4701 ms；五次各 1 MiB 连续下载中位 2.853 Mbps。TCP512 诊断回传约 154.47 KiB/s，真实目标完整回读约 26.03 KiB/s。连续 TCP、诊断包和 SWD 目标数据是三种不同口径，不能互换。

零填充压缩前后，512 虚拟回读中位为 2550.673 / 2563.001 ms；没有建立吞吐收益。按提交长度及命令结构计算，192 包的 DAP 请求体从 98304 降到 17920 字节；这是请求体推算，不含 TCP / IP / Wi-Fi 开销，也不是无线抓包结果。保留该优化的依据是减少无效字节且全部语义 / 功能回归通过。

请求时钟扫描，每档五次读 4 KiB，另完整读取 64 KiB 比对，均通过：

| 请求时钟 | 原生 USB64 | 无线虚拟 USB512 |
| --- | --- | --- |
| 1 MHz | 21.309 KiB/s | 15.084 KiB/s |
| 2 MHz | 38.687 KiB/s | 19.454 KiB/s |
| 4 MHz | 66.420 KiB/s | 17.989 KiB/s |
| 6 MHz | 84.230 KiB/s | 31.452 KiB/s |
| 8 MHz | 101.737 KiB/s | 40.073 KiB/s |
| 10 MHz | 113.449 KiB/s | 40.510 KiB/s |

以上时钟为主机请求值，未测 SWCLK 波形。USB 随请求时钟明显提高，无线仍受长尾影响；结果支持 SWD 执行成本和网络往返 / 调度共同限制的判断，不能据此分配瓶颈百分比。扫描结束恢复请求 2 MHz；高时钟完整烧录 / 调试及其他目标板稳定性仍待验收，不自动提高默认频率。
