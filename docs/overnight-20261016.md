# 2026-10-16 开发与实板验证记录

当前固件0.2.17，连接服务/SDK0.2.8。开发板ESP32-S3、16MB Flash/8MB Octal PSRAM，CPU240MHz、CPU0执行器；目标STM32F103C8、64KiB Flash。电脑2.4GHz热点，板端192.168.137.170，USB64/TCP512。SWD默认请求4MHz；RMT内部数字测量约3.64MHz，未验证外部模拟波形。GPIO4/5为SWDIO/SWCLK；物理NRST缺线，测试均通过软件控制。保留新fixture，未恢复历史应用。

## 完成内容

1. ESP32先接收镜像，CRC32逐片确认、SHA256封存，再由原统一执行器运行RAM算法。完整64KiB在身份/容量/保护预检后允许一次主Flash擦除；局部完整页逐页擦除，选项字节只读。
2. 全镜像板端比较保持必做，去掉重复逐页Verify调度；额外主机SHA256可选。进度区分验证发生位置、终态及未知写入，不自动重放。
3. 内部RAM不足曾使八包短回复停顿；将48KiB Timeline payload移入PSRAM，内部保留任务栈/DMA/控制结构，16000条连续短回复请求通过。无PSRAM时明确内存不足才允许auto回退host。
4. Xtensa慢循环系数及固定时序开销校准，使4MHz请求下DP脉冲由约2.67提高到3.64MHz。USB/无线共用同一SWD内核。
5. 公共健康查询提供RAM/PSRAM余量和最后采集IO失败原因；无需目标owner。RMT测量通过控制屏障，不与采样交错。
6. Node SDK独立取消并等待原COMMIT；C ABI小输出缓冲不重发。烧录后保持本地游标递增；Orbit独立工作树更新SDK、停止旧数据流代际并可重新订阅。启动脚本等待API就绪。
7. 录制区分无效数据与预算超限，新增离线异常分析；CRC/截断/容器校验保持严格。打包根据实际刷入receipt选择PSRAM镜像，不再硬编码旧目录；固件和SDK版本分别记录。

## 性能与完整性

所有Flash测试使用同一全密度65536B fixture，SHA256 `2a65c721fa1be9c4fcddba2a32bb96ccaeece439b517adb167f00ea928c031a4`。每个半字均非0xffff，避免小应用/稀疏镜像夸大速度。

| 测量 | 结果 | 范围 |
| --- | ---: | --- |
| 原增强host调度0.2.13 | 19.804 s中位 | 与probe交替各5次，含主机全回读 |
| 缓存probe0.2.13 | 6.179 s中位 | 同组，含主机额外SHA256 |
| 最终probe0.2.17 | 3.623 s中位 | 5次，电脑暂存+上传+擦写+板端全比较+复位；之后另做独立验收回读 |
| 最终probe再加主机SHA256 | 5.144 s | 1次，非重复中位 |
| 最终标准OpenOCD虚拟USB | 4.753 s | 1次program/verify/reset，之后独立读回/选项字节检查 |

不能用19.804→3.623称OpenOCD提高五倍；这是不同增强路径和校验模式。板端缓存并不能让未经适配的第三方软件自动使用增强烧录命令。

一小时测试：十条独立四级链、十个动态32位字段、叶节点间隔64B、Timeline请求1000us，Watch前4字段/100ms，RTT/5ms。Timeline实测328.30Hz，所有十叶节点各变化326614次。1544458帧录制（163326672B）独立复核通过，SHA256 `55fdcb7e00f1761b9e3ff39fa133ea230e5f4e3321806095182d178598be0d78`。实时消费者缺口、板端ring_dropped/SWD failures、无效数据均0。Timeline每帧超过1ms预算，2418162个请求槽位跳过；不等同于TCP丢包。RTT有1128个fixture生产端跳过，主要是启动前积压，提交字节流连续。

用户新组合为五个三级指针变量＋五个普通变量，叶节点同样相隔64B，24轮3×5s对照：

| 布局/共存 | 1kHz请求实际Hz | 5kHz请求实际Hz |
| --- | ---: | ---: |
| 独立链，单独采样 | 498.08 | 689.83 |
| 独立链，Watch/RTT共存 | 499.02 | 676.22 |
| 共享链，单独采样 | 948.44 | 1179.50 |
| 共享链，Watch/RTT共存 | 951.89 | 1139.74 |

5kHz目标对应200us，独立链共存帧内P50约1275us，共享约693us。提高请求频率主要减少期限网格的等待，不能消除目标读取成本。独立组合需25个物理word读取，共享帧内去重约13个。不得将共享/连续数组结果套用于独立/离散指针。

## 分层验收

- 源码/主机：Flash与采集C状态机64/512容量；106项Python测试、7项Node SDK测试通过。最终TCP64/512 PSRAM配置构建通过。
- ESP32/目标：最终OpenOCD/pyOCD、USB上传边界/CRC/SHA/邻页保留、擦除后取消并暂停、新作业恢复通过。真实TCP close约28.04ms释放；USB和新TCP均不能重放旧COMMIT。
- 通用客户端：真实Node取消和完成竞态、C WinHTTP并发取消与小缓冲不重发、烧录后同一owner二进制流重新订阅通过。有线/无线三订阅、RTT重建各50次通过。
- Orbit：仅独立工作树；1055项测试通过、1项跳过，类型检查/构建通过。真实适配器子进程完成启动前64KiB烧录、三级指针/矩阵Watch/Timeline/RTT及暂停继续，短测约997Hz（共享连续字段），正常退出。不是安装后VS Code UI验收，未修改原Orbit工作区或发布插件。

## 保留的失败与缺口

0.2.13首轮在约430s出现一次partial，根因未证实；同版第二轮10min及最终一小时未复现，不能称该故障已经修复。旧失败文件离线分析可区分1个无效帧和大量有效但超预算的帧。

时钟诊断初版line-reset序列影响AP访问，已改为SWDIO=0空闲序列并恢复GPIO路由；两轮失败记录保留。启动入口曾返回早于API就绪；原始连接拒绝记录保留，后续就绪等待及重新订阅已通过。一次直接TCP断连脚本因服务占用唯一连接超时，尚未接触目标；停止服务后重测通过。

未验收：正式微软驱动签名、Keil/IAR逐项兼容、已安装VS Code界面、真实电脑重启/静默网络黑洞、物理NRST、其他目标族及外部模拟信号质量。当前本机修补驱动为测试签名；不改变Secure Boot/驱动/启动配置。增强Flash仍限于F103C8完整1KiB页镜像。

## 下一步

优先减少每帧SWD物理事务，核对AP posted-read及TAR切换语义后再考虑新批量执行命令；不能靠重放未知操作或跨帧缓存指针换取数字。对具体应用取得地址布局后比较离散/连续普通变量。若要求完整十字段稳定5kHz，应单独评估更高实际SWD时钟及目标侧快照缓冲方案；当前4MHz请求下未达成。
