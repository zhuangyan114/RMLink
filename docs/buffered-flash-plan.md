# ESP32 缓存与板端 Flash 烧录

2026-10-15。起点：RMLink `4531af9`，固件 0.2.11、服务／SDK 0.2.6。用户授权本轮设计、实现及当前 F103C8 的烧录测试；默认请求 SWD 4 MHz，保留 fixture，不恢复旧 Flash。

## 问题与实现范围

现有 `FlashProgrammer` 的 begin/chunk 缓存在电脑进程中。commit 通过无线逐页调用 STM32 RAM loader，核心寄存器设置、轮询、页数据和校验仍反复跨网络。本轮将完整镜像缓存和烧录调度放到 ESP32；仅缓存上传而仍让电脑逐页指挥不能达到本轮目标。

第一版限定当前 F103C8、64 KiB 主 Flash、完整 1 KiB 页镜像。原计划内部 RAM 缓存；首轮实机 begin 返回内存不足且未进入烧录，故改为已确认的 8 MiB PSRAM 作镜像缓存。独立 `-ImageCachePsram` 配置只允许显式 capability 分配使用 PSRAM，原 USB DMA 缓冲、执行任务和正常 malloc 保持内部 RAM；启动内存检查通过后另验收。复用现有 1464 B MIT RAM loader、原 SWD 执行器与目标所有权；不增加 GPIO 执行任务。标准 CMSIS-DAP 的虚拟 USB 路径不变，此优化由通用增强 API/SDK 提供，Orbit 和其他前端均可调用。

## 实施顺序

1. 保存原 EXE／镜像身份，以相同 64 KiB fixture 获取现有增强烧录基线。
2. 新增独立 0x82 Flash 协议：能力、begin、chunk、seal、commit、status、cancel。严格检查范围、会话、操作 id、覆盖、冲突重传、CRC／SHA256；上传及 seal 不擦写目标。
3. ESP32 分配最多 64 KiB 镜像缓存。完成上传并验证 SHA256 后进入 ready；commit 一次有效，重复提交不重新执行。状态保留完成／失败／取消及可能已修改的范围。
4. 同一固定核执行器运行有界状态机：身份／容量与选项字节前置检查、暂停／清理 FPB、装载既有 RAM 算法、逐页擦除／写缓冲／编程／校验、完整 Flash 回读与缓存逐字节比较、选项字节核对、软件复位。主机另外独立回读 SHA256。控制队列在步骤间优先，可取消；未知完成状态不重放。
5. 服务协商能力后优先板端缓存路径；公开 begin 可显式选择 host/probe/auto 用于兼容和对照。新路径分开记录 ESP32 上传、板端阶段、主机独立回读和总耗时，旧固件 auto 回退。
6. 验收：主机 C 状态机模型、协议异常与 host 集成检查；CPU0 TCP64／512 构建；真实有线／无线上传与完整烧录、错误镜像不擦除、重复 commit、取消／断连与占用；同镜像交替重复对照。标准虚拟 USB 调试及三订阅回归。

## 必须保持的约束

- 缓存属于 transport+session+operation_id；外来会话不能查询目标敏感状态、提交或取消，关闭会话释放缓存并在安全边界停止旧作业。
- 缓存断电即失效；不在重新连接或开机后自动续烧。断连时正在执行的目标写入可能已经完成，明确报告，不自动恢复或重放。
- commit 前不改变目标程序；Flash 工作期间拒绝其他目标控制／原始 DAP／采样启动，状态和取消仍可用。一个目标始终只有一个 owner。
- 取消或失败时尽力暂停核心，保留部分完成信息；不把“已上传 ESP32”展示为“STM32 已烧录成功”。只有独立校验完成才报告成功。
- STM32 擦除／编程本身的硬件耗时仍存在；目标是减少无线往返，不预先承诺总耗时或让普通第三方软件自动获得同样增益。

## 首个完整实现检查点

- 短回复突发停顿时内部堆 free=2256 B、largest=1408 B、七个短包未确认。将 48 KiB Timeline 记录 payload 显式移到 PSRAM 后，恢复原 TCP 发送逻辑，连续八包共 16000 请求通过。取消 RX/TX A-MPDU、Nagle、回复合并均未解决，未保留这些试验改动；关闭 TCP oversize 在当前 SDK 不受支持，构建拒绝且未刷入。原 SDK 未修改。
- USB／Wi-Fi 异常脚本通过；实际 TCP close 后旧作业停止、USB owner 可接手、旧 COMMIT 拒绝、新作业完整恢复，释放约 30.42 ms。Node SDK 实机 AbortSignal 取消／新作业恢复、完成后的 cancel 保持终态通过。
- 同一全密度 64 KiB 镜像交替各五次：host 总耗时中位 18.552 s，probe 9.119 s，约 2.03 倍；上传约 0.297 s，板端约 5.35 s。连续读优化后的单次总耗时 7.395 s、主机独立校验 1.481 s。后者尚未当作重复结论。
- 96 项主机测试、7 项 Node SDK 取消测试通过；真实 Flash C 状态机和采样模型通过，64／512 PSRAM 构建通过。新自动回退只接受明确的 BEGIN 内存不足，不从未知传输或 COMMIT 失败回退。
- PSRAM 配置完成 54 轮深度 0..4、共享／独立、独占／Watch+RTT 共存及指针改向／非法分支测试。共存三轮中位：静态 940.98 Hz、共享三级 689.60 Hz、独立四级 245.75 Hz；原 0.2.11 短测对应 963.12／702.12／247.22 Hz，测量时间不同，不能把小差值归因为某一改动。全部无无效帧、消费者缺口和 SWD 失败，期限跳过仍存在。
