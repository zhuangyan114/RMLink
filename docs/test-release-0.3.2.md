# RMLink 0.3.2 测试版验收

本版本为开发测试版，使用 GitHub Pre-release 和 OTA `channel: testing`。正式通道默认不选择此版本。此记录区分主机检查、实板结果和未覆盖条件。

## 条件与镜像

- 日期：2026-10-18；Windows x64，ESP-IDF v5.1.2。
- ESP32-S3，16 MiB Flash、8 MiB Octal PSRAM；target／TCP512／core0／PSRAM／streamdiag／IP TOS 160 配置。
- STM32F103C8，64 KiB Flash；GPIO4 为 SWDIO，GPIO5 为 SWCLK，共地。请求 SWD 时钟 4 MHz，未测量实际波形；物理 NRST 未连接，不纳入本轮。
- 0.3.2 最终应用 888464 字节；SHA256 `2f460bfa51cb3f181b63a22ebc4994fe271e97f5b38f2957851b3f2686841d17`。
- 应用 ELF SHA256 `cccbe2956deb5e22576fe26f6f7cd827a8bf56db7a54f53782b3313c1b874f01`；硬件配置指纹 `16445f574834cf7b`。
- 开始前读取 ESP32 全部 16 MiB Flash 和 STM32 全部 64 KiB 主 Flash，独立计算摘要。备份及设备配置仅保存在本地忽略目录，均不随 Release 发布。

上述第一轮四次升级、回滚及挂载矩阵使用初始 0.3.2 候选 ELF `df6bc83e0aa5cc4405edde6296c987335bfc86fe4019eadb61e75efcf5d218f8`。随后目标回归发现原生 USB READ_MEMORY 不接受补齐的 64 字节请求，修正为接受完整头部并保持输出边界检查；新增真实补齐形态及截断／越界用例。最终应用已重新构建，经原生 USB 上传及 VALID 核对通过，耗时 73.813 秒；后续目标和公开下载测试使用本页列出的最终镜像。

最终镜像上传 32768 字节后实际关闭电脑热点，8 秒后重新开启；设备重新取得 DHCP 地址，原镜像／槽位保持 VALID。主机等待不完整上传的维护超时后自动恢复连接，并能开始新上传再取消；从断网开始约 105.391 秒，包含设计中的约 100 秒维护等待。该结果不代表丢失连接后继续传输原上传。

最终镜像还重新完成了全部设备端错误输入检查和首次启动失败回滚，恢复后 ELF 与本页最终镜像一致、状态 VALID。第一轮候选与最终镜像的原始记录分开保留。

## STM32 与第三方工具回归

- 标准虚拟 CMSIS-DAP → Wi-Fi → SWD：OpenOCD 完整擦写／校验 64 KiB fixture、软件复位，以及暂停／继续、寄存器、RAM、硬件断点、单步、DWT、故障清除和取消恢复通过。最终镜像该次 OpenOCD 烧录／校验 4.166 秒，无 Error 行；选项字节未变。
- pyOCD 通过精确虚拟 USB 序列号选择设备，目标识别、暂停、PC 读取及继续运行通过。
- Node SDK 八包满容量／顺序校验和设备身份通过；WinHTTP C DLL 连接、CPUID、fixture 内存及 Running 状态通过。
- 原生 USB64 与 Wi-Fi 三订阅、严格录制、指针字段、错误字段隔离、慢消费者与独立录制、RTT 连续重配 50 次通过。故意超预算和错误地址用例中的失败计数属于预期检测，不计为正常采集通过。
- 采集中断开 STA 后约 4.756 秒自动恢复连接和虚拟 USB。旧租约保持失效，旧录制封存为失败且恢复后摘要不变，不重放旧订阅；新租约可以重新采集。
- 活动三订阅采集期间，实际调用降级安装被占用保护拒绝；原 owner 和连接保持，采集继续。

一次压力脚本在回滚测试后误沿用了 USB64，却请求复杂十字段 1 kHz；约 30 秒时检测到 1141 帧板端缓存丢弃并终止。原始记录保留，不能记为 Wi-Fi 失败或采集通过。脚本现支持 `--transport`，启动前核对实际承载，不符即终止。本轮分别用明确的 Wi-Fi 1 kHz 和 USB 100 Hz 条件验收；USB64 复杂采样 1 kHz 不在通过范围内。

## 持续采集

Wi-Fi 实际持续 900.008 秒：72 MHz F103、请求 4 MHz SWD，五条独立三级指针链加五个直接字段，字段间隔 64 字节，与 10 Hz Watch 和 5 ms RTT 轮询共存。Timeline 请求 1000 Hz、实测 **999.17 Hz**；录制 **964594 帧／103510248 字节**，独立文件 SHA256、CRC、序号、字段身份和动态变化检查通过。无无效字段、板端缓存丢弃、SWD 失败、实时消费者缺口或 RTT 字节缺口。

本次为非严格实时模式：录制中仍有 746 次序号跳过和 76245 帧超预算标志，`invalid_data_samples=0` 与 `budget_overrun_samples=76245` 分开记录；不能称为严格无损 1 kHz 或硬实时。实时消费者未落后，有限历史队列正常淘汰旧帧，独立录制不依赖该历史队列。末尾 8192 个间隔窗口的 P50／P99 为 1000／1233 微秒，不代表整个 15 分钟的全局分位数。

原生 USB64 以相同字段布局、Watch／RTT 共存运行 300.013 秒，Timeline 请求 100 Hz、实测 100.00 Hz。录制 51754 帧／5367432 字节，独立摘要／CRC／字段检查通过；序号缺口、无效数据、超预算、板端缓存丢弃、SWD 失败、消费者缺口与 RTT 字节缺口均为 0。

修复分支的 [Linux CI 39139872802](https://github.com/zhuangyan114/RMLink/actions/runs/39139872802) 已成功完成 safe、target、target-psram 三种配置的干净编译、OTA 镜像与清单校验及构建资产上传。该结果属于编译检查，额外两种板型未实板验证；CI 产物没有覆盖已发布且经过实板验收的应用。保留 v0.3.2 发布标签与原二进制不变，环境修复和发布后报告作为后续分支提交记录。

## 验证边界

- 本轮 RTS 复位不是物理断电；写入、提交或首次启动时真实断电仍待覆盖。
- 未连接物理 NRST，未测量 SWCLK，未覆盖其他目标芯片／ESP32 板型及真实 SWD WAIT 电气故障。
- 使用现有本机修补并测试签名的 USBip UDE；没有更换内核驱动，没有完成正式微软签名发布验收。开发包不附带内核驱动。
- 不包括已安装 VS Code／Orbit 界面逐项操作、电脑重启后的全流程或长期跨网络兼容性。
- SHA256 提供完整性检查；本版本未启用安全启动／签名固件，也没有写入 eFuse。
- 启动回滚时设备能恢复原镜像，当前客户端等待目标 ELF 的超时提示仍是通用未确认错误，不能将该提示当作设备没有回滚。

原始证据仅留在本机 `artifacts/tests/full-acceptance-20261018/` 和 `artifacts/logs/full-acceptance-*`。其中可能包含设备身份、现场内存和本机路径，不作为公开下载资产。
