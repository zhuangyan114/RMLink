## 不变的约束

- USB、TCP 和采样共用一个 SWD 执行器，整段目标会话保持互斥。control > watch > timeline > background；Abort 独立接收，外来会话不能改变时钟或取消 owner。
- 保留返回实际数量、FAULT / WAIT / NO_ACK、执行期限和断连清理。完成状态未知的写入不自动重放。
- 标准 CMSIS-DAP 能力按实现声明；增加逻辑包不等于增加 Atomic / SWO / JTAG 能力。
- 原生 USB 为 Full-Speed，端点最大物理包仍为 64 字节。评估更大的 DAP 逻辑包时必须处理多个 USB 物理包，不能通过虚报 High-Speed 达到目的。
- 原 STM32 64 KiB 备份哈希为 75bcca6e52d436f377542beb94629ef101d153e214ef085b6af7893d40b347ff，保留作历史恢复源。后续默认保留测试程序并完整回读核对该 fixture；恢复旧程序改为显式选项。最后记录目标状态并释放 owner。

## 决策与回退

每阶段在 artifacts/logs 下建立独立目录，保留原始报告和旧基线，不覆盖此前验收。性能报告记录固件 / 服务 / 脚本版本和哈希。协议容量变化前保存当前可用固件与连接服务产物。

任何内容错误、会话越权、失去 Abort、启动崩溃或目标恢复失败，都先停止性能结论并恢复已验证版本。出现同环境吞吐下降或控制延迟恶化时，分析原因，保持稳定版本，不仅以大块吞吐决定是否合入。

本轮首先完成阶段 2，接着按实测推进阶段 3 和阶段 4；后续阶段按依赖顺序推进。进展与结果在本文件和 development-status.md 更新，阶段未完成时明确保留待办。

最新检查点：固件 0.1.6 / 服务 0.1.4，512 无线逻辑包、独立地址流水线、零填充压缩已实际运行。同会话 64 / 512 内存预算交替读取约 2.57 倍，最终虚拟 OpenOCD 全流程约 7.28 秒，原程序恢复；完整结果、口径、验证矩阵和后续事项见 [performance-results.md](performance-results.md)。

## 第一个实施检查点

以下是历史数据，不能作为最终推荐的流水线实现。后续审计发现，跨已提交包缓存 TAR 会在前一个包只完成一部分时偏移后续地址；当前流水线已替换为每包 TAR + 读写的标准 DAP_Transfer，并增加部分完成地址检查。64 字节安全版全 Flash 读取为 1152 条命令，扩容后的算法和最终结果另行记录。

2026-10-14，固件仍为 0.1.5，服务构建为 0.1.2。阶段 2 完成第一轮实现、6 项 MEM-AP 模型测试以及实际 USB / TCP / 虚拟 USB 比较。连续回读 64 KiB 的命令数 2304 → 1216、批次数 288 → 152。4 KiB 各 5 次交替旧 / 新算法，64 KiB 先做 3 次交替探索，后续稳定统计增加重复；原始数据和摘要见 performance-stage2-results.json。
